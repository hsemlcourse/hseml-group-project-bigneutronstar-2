## 1. Введение и постановка задачи

- **Цель проекта:** прогнозирование краткосрочного направления движения цены фьючерса на золото (GC) на основе исторических рыночных данных. Практическая ценность - возможность использования в торговых стратегиях для принятия решений о входе/выходе из позиции.
- **Формулировка задачи:** бинарная классификация. Target = 1, если цена закрытия через N часов выше текущей; target = 0 - иначе. Рассмотрены горизонты прогнозирования h=1, h=4 и h=24 (часы).
- **Обоснование метрики качества:** основная метрика - **ROC-AUC**, так как она инвариантна к порогу классификации и устойчива к небольшому дисбалансу классов. Дополнительно используются Accuracy и F1-score. Предпочтение отдается ROC-AUC, поскольку в задаче финансового прогнозирования важна способность модели ранжировать наблюдения по вероятности роста, а не конкретное бинарное решение.

---

## 2. Поиск и описание данных

- **Источник данных:** часовые котировки фьючерса на золото (GC). Файл `gold_data_1h_cleaned.csv` (один из двух файлов датасета с Kaggle).
- **Почему выбран именно этот датасет:** из двух доступных (часовой и дневной) выбран часовой, так как он содержит больше наблюдений (11 423 vs 6 383) и лучше подходит для задачи краткосрочного прогнозирования.
- **Описание датасета:**
  - Объем: 11 423 строки x 14 столбцов
  - Период: февраль 2024 - февраль 2026
  - Признаки:

| Столбец | Тип | Описание |
|---|---|---|
| DateTime | datetime | Временная метка (UTC-5) |
| Date, Time | string | Дата и время отдельно |
| Year, Month, Day, Hour | int | Календарные компоненты |
| Open, High, Low, Close | float | Цены OHLC |
| Volume | int | Объем торгов |
| Price_Change | float | Абсолютное изменение цены |
| Price_Change_Percent | float | Процентное изменение цены |

  - Пропуски: 1 значение в Price_Change / Price_Change_Percent (первая строка). OHLCV без пропусков.
  - Дубликаты: отсутствуют.
  - Данные отсортированы по времени.

## 3. Обработка и подготовка данных

- **Очистка:**
  - Пропуски: строки с пропусками в OHLC удалены (на практике таких не было), пропуск Price_Change в первой строке не влияет на пайплайн, так как этот столбец не используется как признак.
  - Дубликаты: проверены по DateTime - дубликатов нет.
  - Выбросы: специальная обработка не проводилась, так как данные представляют реальные рыночные котировки и экстремальные значения несут информацию.
  - Типы данных: DateTime приведен к datetime (UTC), числовые столбцы корректны.
  - Удалены строки с нулевым объемом (404 строки) - они соответствуют периодам без торговой активности.

- **Feature engineering (39 признаков):**

| Группа | Признаки | Описание |
|---|---|---|
| Доходности | return_1, return_2, return_4, return_8, return_24 | Процентное изменение цены за N баров |
| Ценовые лаги | close_lag_{1,2,3,4,8}_ratio | Отношение текущей цены к цене N баров назад |
| Волатильность | rolling_std_{6,12,24,48} | Стандартное отклонение цены в окне N баров |
| Отклонение от MA | dev_from_ma_{6,12,24,48} | Относительное отклонение цены от скользящей средней |
| High-Low range | hl_range, hl_range_rolling_6 | Нормированный размах и его скользящее среднее |
| Объем | volume_ratio_6, volume_ratio_24 | Отношение текущего объема к скользящему среднему |
| Свечные паттерны | upper_shadow, lower_shadow | Нормированные верхняя и нижняя тени свечи |
| RSI | rsi_14, rsi_6 | Relative Strength Index с периодами 14 и 6 |
| MACD | macd, macd_signal, macd_hist | MACD-линия, сигнальная линия и гистограмма (нормированы ценой) |
| Bollinger Bands | bb_upper/lower/width/position_{12,24} | Расстояние до верхней/нижней полосы, ширина, позиция внутри полос |
| Календарные | hour, dayofweek | Час дня и день недели |

  Все признаки используют только прошлую информацию - lookahead leakage исключен.

- **Сплит данных:**
  - Стратегия: временной (chronological) holdout split, 80% train / 20% test.
  - Train: февраль 2024 - сентябрь 2025 (~8 758 наблюдений).
  - Test: сентябрь 2025 - февраль 2026 (~2 190 наблюдений).
  - Никакого случайного перемешивания - train строго предшествует test по времени.
  - Leakage предотвращен: (1) признаки строятся только на прошлых данных; (2) target использует будущую цену, но строки, где будущее неизвестно, удалены; (3) split строго хронологический.
  - Дополнительно применена walk-forward cross-validation (5 фолдов) для более надежной оценки.

## 4. Baseline-модель

- **Модель:** Logistic Regression (solver=lbfgs, max_iter=1000) на стандартизированных признаках (StandardScaler).
- **Результаты на test (horizon=1):**

| Метрика | Значение |
|---|---|
| Accuracy | 0.5066 |
| F1-score | 0.5714 |
| ROC-AUC | 0.4916 |

- Baseline-модель показывает ROC-AUC чуть ниже случайного (0.50), что говорит о слабом линейном сигнале при часовом горизонте.

## 5. Эксперименты

### 5.1 Сравнение горизонтов прогнозирования (holdout)

| Горизонт | Модель | Accuracy | F1-score | ROC-AUC |
|---|---|---|---|---|

| h=1 | RandomForest | 0.5308 | 0.6601 | 0.5136 |

| h=4 | GradientBoosting | 0.5201 | 0.5830 | 0.5061 |

**Вывод:** Наилучший ROC-AUC на holdout показал GradientBoosting при h=1 (0.5279), однако на walk-forward CV горизонт h=24 оказался стабильнее.

**Вывод:** Walk-forward CV подтверждает, что горизонт h=24 дает более стабильный (хоть и слабый) сигнал. Лучший средний ROC-AUC = 0.5252 (GradientBoosting).

## 6. Финальная модель и интерпретируемость

- **Финальная модель:** GradientBoosting (tuned) с горизонтом h=24.
- **Параметры:** n_estimators=300, max_depth=5, learning_rate=0.05, min_samples_leaf=20, subsample=0.8.
- **ROC-AUC на holdout:** 0.5254. **WF-CV ROC-AUC:** 0.5281.
- **Интерпретация:** модель опирается в первую очередь на волатильность (rolling_std_48, rolling_std_24), MACD-компоненты (macd_signal, macd, macd_hist) и ширину полос Боллинджера (bb_width_24). Это согласуется с финансовой логикой: периоды высокой/низкой волатильности имеют разные характеристики предсказуемости. День недели (dayofweek) также вносит вклад - вероятно, из-за разной ликвидности в разные дни.
- Сигнал очень слабый (ROC-AUC ~ 0.52-0.53), что ожидаемо для задачи краткосрочного прогнозирования на высоколиквидном рынке.

## 8. Заключение и выводы

### Итоги

- Поставлена задача бинарной классификации направления движения цены фьючерса на золото.
- Построен пайплайн: загрузка - очистка - 39 признаков (включая RSI, MACD, Bollinger Bands) - target - временной split - обучение - оценка.
- Протестированы 3 горизонта прогнозирования (h=1, h=4, h=24).
- Применена walk-forward cross-validation (5 фолдов) для надежной оценки.
- Проведен тюнинг гиперпараметров по сетке с использованием walk-forward CV.
- Обучены и оценены 3 модели: Logistic Regression (baseline), Random Forest, Gradient Boosting.
- Лучший результат: GradientBoosting (tuned) при h=24, ROC-AUC = 0.5254 (holdout) / 0.5281 (WF-CV).

### Ключевые выводы

1. Все модели показывают очень слабый сигнал (ROC-AUC 0.50-0.53). Это ожидаемый результат для краткосрочного прогноза на высоколиквидном рынке.
2. Более длинный горизонт (h=24) дает более стабильный сигнал, чем h=1 или h=4.
3. Добавление технических индикаторов (RSI, MACD, BB) немного улучшило качество по сравнению с базовым набором (26 vs 39 признаков).
4. Walk-forward CV дает более пессимистичные, но более надежные оценки, чем одиночный holdout.
5. Тюнинг гиперпараметров дал небольшое улучшение ROC-AUC.

### Ограничения

- Сигнал очень слабый - модель не имеет практической ценности в текущем виде.
- Не использованы данные из альтернативных источников (макроиндикаторы, индекс доллара, доходности облигаций).
- Не тестировались нейросетевые архитектуры (LSTM, Transformer).

### Возможные улучшения

- Добавить макроэкономические индикаторы (DXY, UST yields, VIX).
- Попробовать нейросетевые модели (LSTM, Temporal Fusion Transformer).
- Расширить пространство поиска гиперпараметров (Optuna).
- Применить стекинг/блендинг моделей.
- Backtesting торговой стратегии для оценки экономического эффекта.
