## 1. Введение и постановка задачи

- **Цель проекта:** прогнозирование краткосрочного направления движения цены фьючерса на золото (GC) на основе исторических рыночных данных. Практическая ценность — возможность использования в торговых стратегиях для принятия решений о входе/выходе из позиции.
- **Формулировка задачи:** бинарная классификация. Target = 1, если цена закрытия через 1 час выше текущей; target = 0 — иначе.
- **Обоснование метрики качества:** основная метрика — **ROC-AUC**, так как она инвариантна к порогу классификации и устойчива к небольшому дисбалансу классов. Дополнительно используются Accuracy и F1-score. Предпочтение отдаётся ROC-AUC, поскольку в задаче финансового прогнозирования важна способность модели ранжировать наблюдения по вероятности роста, а не конкретное бинарное решение.

---

## 2. Поиск и описание данных

- **Источник данных:** часовые котировки фьючерса на золото (GC), собранные из Yahoo Finance. Файл `gold_data_1h_cleaned.csv`.
- **Почему выбран именно этот датасет:** из двух доступных (часовой и дневной) выбран часовой, так как он содержит больше наблюдений (11 423 vs 6 383) и лучше подходит для задачи краткосрочного прогнозирования.
- **Описание датасета:**
  - Объём: 11 423 строки × 14 столбцов
  - Период: февраль 2024 — февраль 2026
  - Признаки:

| Столбец | Тип | Описание |
|---|---|---|
| DateTime | datetime | Временная метка (UTC-5) |
| Date, Time | string | Дата и время отдельно |
| Year, Month, Day, Hour | int | Календарные компоненты |
| Open, High, Low, Close | float | Цены OHLC |
| Volume | int | Объём торгов |
| Price_Change | float | Абсолютное изменение цены |
| Price_Change_Percent | float | Процентное изменение цены |

  - Пропуски: 1 значение в Price_Change / Price_Change_Percent (первая строка). OHLCV без пропусков.
  - Дубликаты: отсутствуют.
  - Данные отсортированы по времени.

## 3. Обработка и подготовка данных

- **Очистка:**
  - Пропуски: строки с пропусками в OHLC удалены (на практике таких не было), пропуск Price_Change в первой строке не влияет на пайплайн, так как этот столбец не используется как признак.
  - Дубликаты: проверены по DateTime — дубликатов нет.
  - Выбросы: специальная обработка не проводилась, так как данные представляют реальные рыночные котировки и экстремальные значения несут информацию.
  - Типы данных: DateTime приведён к datetime (UTC), числовые столбцы корректны.
  - Удалены строки с нулевым объёмом (404 строки) — они соответствуют периодам без торговой активности.

- **Feature engineering (26 признаков):**

| Группа | Признаки | Описание |
|---|---|---|
| Доходности | return_1, return_2, return_4, return_8, return_24 | Процентное изменение цены за N баров |
| Ценовые лаги | close_lag_{1,2,3,4,8}_ratio | Отношение текущей цены к цене N баров назад |
| Волатильность | rolling_std_{6,12,24,48} | Стандартное отклонение цены в окне N баров |
| Отклонение от MA | dev_from_ma_{6,12,24,48} | Относительное отклонение цены от скользящей средней |
| High-Low range | hl_range, hl_range_rolling_6 | Нормированный размах и его скользящее среднее |
| Объём | volume_ratio_6, volume_ratio_24 | Отношение текущего объёма к скользящему среднему |
| Свечные паттерны | upper_shadow, lower_shadow | Нормированные верхняя и нижняя тени свечи |
| Календарные | hour, dayofweek | Час дня и день недели |

  Все признаки используют только прошлую информацию — lookahead leakage исключён.

- **Сплит данных:**
  - Стратегия: временной (chronological) holdout split, 80% train / 20% test.
  - Train: февраль 2024 — сентябрь 2025 (~8 776 наблюдений).
  - Test: сентябрь 2025 — февраль 2026 (~2 195 наблюдений).
  - Никакого случайного перемешивания — train строго предшествует test по времени.
  - Leakage предотвращён: (1) признаки строятся только на прошлых данных; (2) target использует будущую цену, но строки, где будущее неизвестно, удалены; (3) split строго хронологический.

## 4. Baseline-модель

- **Модель:** Logistic Regression (solver=lbfgs, max_iter=1000) на стандартизированных признаках (StandardScaler).
- **Результаты на test:**

| Метрика | Значение |
|---|---|
| Accuracy | 0.5339 |
| F1-score | 0.6577 |
| ROC-AUC | 0.5036 |

- Baseline-модель показывает ROC-AUC лишь чуть выше случайного (0.50), что говорит о слабом линейном сигнале в данных.

## 8. Заключение и выводы

### Текущие итоги (CP1)

- Поставлена задача бинарной классификации направления движения цены фьючерса на золото на часовом горизонте.
- Построен пайплайн: загрузка → очистка → 26 признаков → target → временной split → обучение → оценка.
- Обучены 3 модели: Logistic Regression (baseline), Random Forest, Gradient Boosting.
- Лучший результат: Random Forest с ROC-AUC = 0.5090.
- Все модели показывают очень слабый сигнал (ROC-AUC ≈ 0.50–0.51). Это ожидаемый результат для краткосрочного прогноза на высоколиквидном рынке.

### Ограничения
- Один фиксированный горизонт (h=1 час) — возможно, для более длинных горизонтов сигнал сильнее.
- Набор признаков ограничен (нет классических технических индикаторов: RSI, MACD, Bollinger Bands).
- Используется один holdout split — нет walk-forward cross-validation.
- Гиперпараметры не оптимизированы.

### Возможные улучшения
- Увеличить горизонт прогнозирования (h=4, h=24).
- Добавить технические индикаторы (RSI, MACD, Bollinger Bands).
- Walk-forward cross-validation для более надёжной оценки.
- Тюнинг гиперпараметров (GridSearch / Optuna).
- Ансамблевые методы (стекинг).
- Анализ экономического значения прогнозов (backtesting торговой стратегии).
